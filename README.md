# 主题阅读 · TopicFeed

按话题浏览 RSS / Atom 订阅，跟踪文章修订历史并在界面里对比版本。纯 Python 标准库实现，无需安装依赖。

```bash
./run.sh start          # http://127.0.0.1:8765
./run.sh stop
python3 -m unittest discover -s tests -v   # 52 个测试
```

首次启动会自动登记三组本地演示源，数据落在 `data/topicfeed.db`（可用 `TOPICFEED_DB` 覆盖）。

## 功能与规则

### 订阅与浏览
* 录入 RSS 2.0 / Atom 1.0 地址（`https://…`），也可用内置 `fixture://<slug>` 演示源。
* 按话题分组；支持搜索标题/摘要、按源筛选。
* 左侧每个本地源都有一个**版本下拉框**，切换后立刻重新抓取该版本，便于查看"源更新后"的表现。
* 打开一篇文章可看到标题、正文、发布时间、更新时间、首次收录时间、历次修订、出现过的所有链接和问题记录。

### 文章身份（不会把不同文章合并）
优先级严格如下：

1. **源内稳定标识**（RSS `guid` / Atom `id`）——首选。
2. **规范化链接**（仅在缺标识时使用）。规范化规则固定且可测：解析相对链接 → 小写 scheme/host、去默认端口 → 去掉 `#fragment` → **仅**删除常见投放参数（`utm_*`、`fbclid` 等）→ 其余查询串排序 → 去掉末尾 `/`。路径大小写和业务参数一律保留。
3. **内容指纹**（既无标识也无链接时）。指纹包含标题 + 发布时间 + 正文，因此**标题相同但内容不同的两条文章不会被合并**。若一条条目连标题之外的任何信息都没有（无正文、无日期），就无法与同名的其他条目区分，此时**不猜测**：该条目不入库，只记一条 `missing_identity` 问题说明原因（重复刷新也不会让文章列表增长）。只有图片的条目会用图片地址区分。

补充规则：
* 标题从不作为身份依据。
* 源后来开始提供 `guid`，或某轮只有链接的条目突然拿到了标识，都会**提升**已有记录的身份并保留修订历史，不会产生重复文章。
* 反过来，两条 `guid` 不同的文章即使共用同一个链接，也不会被合并。
* 链接只接受 `http` / `https`：`javascript:`、`data:` 等不能当永久链接；端口写坏或 IPv6 残缺的链接会退回内容指纹，且**不会让整份文档解析失败**。
* 已有 `guid` 的记录，若同一链接被源挪作他用（标题/正文/发布时间都换），按新文章处理，不覆盖旧历史；已提升为 `guid` 的记录再次见到「只有链接、无 guid」的条目时，同样要求标题与发布时间相符。
* 如果一条记录**本来就只有链接**作为身份依据，源用同一链接发了一篇完全不同的文章，系统无法区分「换了文章」和「改了文章」，会按修订处理。这是链接型身份的固有边界（宁可保留历史，也不凭猜测拆成两篇）。

### 时间
* `published_at`、`updated_at` **分开存储**，均来自源。
* 无法解析的日期**不会**被替换成抓取时间。`2026-11-11`（只有日期没有时刻）、`02 Nov 26`（两位年份）都按歧义日期拒绝，而不是替源猜测。
* 常见变体照常接受：`+0800`、`UTC`、`GMT`、`PDT` 等命名时区、完整星期名、结尾注释、小写 `z`。
* `first_seen_at` 是我们自己的收录时间，界面上与发布时间并列显示。补发的旧文（发布时间远早于收录时间）会打上「补发旧文」标记。
* 发布时间缺失的轮次不会清掉已知的发布时间。
* 若源**从未**提供发布时间、只提供更新时间，第一次见到的 `updated` 会被当作发布时间固定下来，后续编辑不会把它一路拖到今天；修订仍以 `updated` 记录。

### 修订历史
* 修订签名 = 标题 + 正文纯文本。只有**可观察状态变化**才追加修订。
* 仅 `updated` 时间变了、正文没变 → 不新增修订。
* 重复抓取完全相同的内容（即使 ETag 变化）→ 条目数、修订数都不增长。
* 某一轮缺了标题、或正文变成空串，视为「这一轮描述得更少」而非「文章被改空」：保留已有标题/正文，不新增修订，也不清空已存正文（空正文仍会记 `empty_body` 问题）。
* 界面可选任意两个修订做左右并排对比，并给出统一 diff；只改标题也会单独提示。

### 旧文章保留
* 源只返回最近几篇时，本轮没出现的文章**不删除**，只标记 `missing_rounds` 与本轮未见。
* 再次出现时标记自动清零。
* 列表可选择是否显示这些旧文。

### 抓取与容错
* **条件请求**：保存 `ETag` / `Last-Modified`，下次带上 `If-None-Match` / `If-Modified-Since`；304 是成功但零写入，同时视为源已恢复，清除此前的源级错误。强制刷新可跳过 304 短路。
* **单源暂停**：暂停的源不会被自动刷新，但可手动刷新，已收录文章保留。
* **失败重试**：失败按 30s → 2m → 10m → 30m → 1h → 2h 退避（带抖动）。后台调度器每 5 分钟（`TOPICFEED_INTERVAL`）只抓取到期的源；界面可「清除重试计时」让下一轮立即尝试。
* **失败隔离**：坏 XML、HTTP 4xx/5xx、网络错误只影响该源，其它源照常刷新。整批刷新中单个源的异常也会被捕获并记为 `internal_error`。
* **非法地址**：录入时即校验地址；端口越界、主机含空格、残缺 IPv6 会直接拒绝（`bad_request`）。若已存在这样的旧记录，抓取会返回 `bad_url` 而不重试、不抛异常。
* **可诊断**：坏 XML → `bad_xml`；异常日期 → `bad_date`（并注明 `unparseable date` 或 `date without a time is ambiguous`）；空正文 → `empty_body`；缺标识 → `missing_identity`。问题按源/条目/种类聚合，记录出现次数；只有**本轮重新解析过且不再出现**的问题才标记为已解决（源出错或条目没出现在本轮列表里时保持未解决，避免误报）。单条坏条目不影响同源的好条目入库。

### 导出
勾选文章后可导出 **JSON**（含正文、纯文本、全部修订、链接历史、问题记录、来源抓取日志）或 **Markdown**（文章 + 修订历史 + 来源记录）。

## 内置演示源

| slug | 话题 | 版本与用途 |
| --- | --- | --- |
| `tech-daily` | 技术 | `v1` 初始 3 篇；`v2` 补发 2019 年旧文（链接带 utm 参数）；`v3` 换链接 / 只改标题 / 旧文从最近列表中消失 / 两篇同题不同文；`v4` 正文实质修改；`v5` 与 v4 完全相同但 ETag 不同 |
| `design-notes` | 设计 | Atom 源。`v1` 两篇；`v2` 一篇正文追加、一篇仅改标题；`v3` 新增一条没有 `<id>` 的条目 |
| `error-lab` | 运维 | `v1` 坏 XML；`v2` 异常日期 + 空正文 + 只有图片；`v3` 坏条目与健康条目并存；`v404` / `v500` 模拟 HTTP 错误 |

快速演示"换链接不新增文章 + 修订对比"：

1. 选中「技术日报」，版本选 `v1`，刷新。
2. 切到 `v3`：A 文章换了链接，条目数不变；B 只改标题，成为一次修订。
3. 切到 `v4`：A 正文有实质变化，出现第二次修订，点「对比」查看左右差异。
4. 切到 `v5`：内容与 v4 相同，条目和修订数都不变。

## HTTP API（节选）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 话题、源、文章、未解决问题、调度器状态 |
| GET | `/api/entries/{id}` | 文章详情（含修订、链接历史、问题） |
| GET | `/api/entries/{id}/diff?left=1&right=2` | 两次修订的对比 |
| GET | `/api/feeds/{id}` | 源的最近抓取日志与问题 |
| POST | `/api/feeds` | `{"url": "...", "topic": "..."}` 订阅 |
| POST | `/api/feeds/{id}/refresh` | 抓取单个源 |
| POST | `/api/feeds/{id}/version` | `{"version": "v3"}` 切换本地源版本并抓取 |
| POST | `/api/feeds/{id}/pause` | `{"paused": true/false}` |
| POST | `/api/feeds/{id}/retry` | 立即重试 |
| POST | `/api/feeds/{id}/clear-backoff` | 清除重试计时 |
| POST | `/api/refresh` | `{"force": true}` 刷新全部 |
| POST | `/api/export` | `{"ids": [...], "format": "json"\|"markdown"}` |

所有订阅正文在渲染前都会经过允许列表 HTML 清洗（保留常见排版标签，去掉脚本、内联事件和非 http(s) 资源）。

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `TOPICFEED_HOST` | `127.0.0.1` | 监听地址 |
| `TOPICFEED_PORT` | `8765` | 端口 |
| `TOPICFEED_DB` | `data/topicfeed.db` | SQLite 路径 |
| `TOPICFEED_INTERVAL` | `300` | 后台刷新间隔（秒） |
| `TOPICFEED_NO_SCHEDULER` | – | 设为 `1` 关闭后台调度 |
| `TOPICFEED_LOG` | – | 设为任意值输出访问日志 |

## 代码结构

```
app/feedparse.py   解析 RSS/Atom、日期、链接规范化
app/store.py       SQLite 模式、身份解析、修订、保留、导出、diff
app/fetcher.py     HTTP / fixture 抓取、条件请求、退避
app/refresh.py     单源与整批刷新、暂停、重试、后台调度器
app/sanitize.py    订阅正文 HTML 清洗
app/main.py        HTTP 服务与 JSON API
app/static/        前端（无构建步骤）
fixtures/          本地演示源与版本清单
tests/test_core.py 52 个测试
```
